# Java Learning System
## ゲーム要素を取り入れたJava学習支援システム

> Java Bronzeの学習を、ただ問題を解くだけではなく「短いゲームを次々クリアする体験」に変えるWebアプリ。

---

## 1. プロジェクト概要

本プロジェクトは、Java Bronzeを学習している初学者を対象としたJava学習支援Webアプリである。

一般的な資格学習では、

```text
問題を解く
  ↓
間違える
  ↓
解説を読む
  ↓
もう一度解く
```

という繰り返しになりやすく、「勉強している」という感覚が強くなって、何度も繰り返すモチベーションを維持しにくい。

そこで本システムでは、

```text
問題を解く
  ↓
ミニゲームを操作する
  ↓
正解・不正解を判定
  ↓
スコア・コンボなどでフィードバック
  ↓
間違えた問題を復習
```

という流れを作り、Javaの知識を使って短時間のゲームをクリアしていく学習体験を目指す。

### コンセプト

**「Java Bronzeの試験問題を解いている」ではなく、  
「Java Bronzeの知識を使って、短いゲームを次々クリアしている」と感じられる学習体験。**

---

# 2. このシステムで解決したい問題

## 2.1 学習が単調になりやすい

Java資格の学習では、問題演習と解説の繰り返しになりやすい。

そのため、

- 同じ形式の問題を繰り返すと飽きる
- 間違えた問題を再び解くのが面倒
- 学習時間が長く感じる
- 自分の苦手分野が分かりにくい

という問題がある。

## 2.2 長い問題文をそのままゲーム画面に載せる問題

Javaの問題にはコードや説明文が長いものもあり、ゲーム画面にそのまま表示すると、

- 文字量が多い
- 画面が読みにくい
- ゲームらしい操作感が失われる

という問題がある。

そのため、本システムでは長い試験問題をそのままゲーム化するのではなく、Java Bronzeの学習範囲を参考にした**短く理解しやすいオリジナル問題**を中心にする。

# 4. システムの特徴

## 4.1 選択式問題

コードを直接入力する問題だけに限定せず、ゲームとして操作しやすい選択式を中心とする。

対応予定：

- A～E / 1つ選択
- A～G / 1つ選択
- A～E / 2つ選択
- A～G / 2つ選択
- A～G / 3つ選択
- コード選択 A～E / 1つ選択
- コード選択 A～G / 2つ選択

今後、必要に応じて問題形式を追加する。

## 4.2 問題ごとの制限時間

すべての問題に同じ制限時間を設定するのではなく、問題の難易度や想定される回答時間に応じて個別に設定する。

目的：

- 素早くJavaコードを読み取る練習
- 本番試験を意識した時間感覚
- ゲームとしての緊張感

## 4.3 短いコード中心の問題

ゲーム画面では、長い問題文を避け、短いコードと短い問いを中心に表示する。

例：

```java
int score = 80;
```

**scoreの型は？**

```text
A int
B double
C String
D boolean
```

別の例：

```java
int x = 10;
int y = 3;
x % y
```

**結果は？**

```text
A 0
B 1
C 3
D 30
```

ゲーム中の説明は短くし、詳しい説明は結果画面・復習画面で確認できる構成を目指す。

# 5. ミニゲーム構想

本プロジェクトでは、問題を解くたびに操作方法が変わることで、単調な問題演習にならないようにする。

## 基本コンセプト

**「問題が変わる → 操作が変わる → ミニゲームも変わる」**

ただし、ミニゲームを大量に作ること自体を目的にはしない。

完成度を優先し、まず4種類をMVPとして実装する。

---

## 5.1 Code Target

### 概要

選択肢の中から正しい答えを狙って選ぶゲーム。

### 向いている問題

- A～E / A～Gの単一選択
- コードの結果
- 型
- 条件式
- 演算子
- 基本文法

### 操作イメージ

```text
┌────────────────────────────┐
│ SCORE 1200       TIME 05   │
├────────────────────────────┤
│                            │
│ int score = 80;            │
│                            │
│ score の型は？             │
│                            │
│ [ A int ]   [ B double ]   │
│ [ C String] [ D boolean ]  │
│                            │
└────────────────────────────┘
```

---

## 5.2 Code Whack-a-Mole

### 概要

表示される選択肢の中から正しい答えを素早く選択するゲーム。

### 特徴

- 素早い判断
- 正解時の演出
- 不正解時のフィードバック
- コンボとの相性が良い

---

## 5.3 Typing Samurai

### 重要な方針

Typing Samuraiは**コードを直接入力するゲームにはしない**。

Javaの問題は選択式のままにして、回答方法だけをキーボード入力にする。

例：

```text
int score = 80;

score の型は？

A int
B double
C String
D boolean

キーボードで答えろ！

→ A
```

これにより、

- Javaコードを入力する難しさ
- 長い文字列を入力する負担

を増やさずに、

**キーボードを使って答える気持ちよさ**

を作る。

---

## 5.4 Code Breaker

### 概要

複数の正解を選んでロックやブロックを解除するゲーム。

### 対応問題

- 2つ選択
- 3つ選択
- 複数の正しいコード・記述を選ぶ問題

例：

```text
正しい記述を2つ選べ！

[ A ] [ B ] [ C ] [ D ] [ E ]
```

正解するとロックが解除される演出を行う。

# 7. 復習・リベンジ機能

本システムでは、間違えた問題を単に「不正解」で終わらせない。

## 基本フロー

```text
問題を解く
   ↓
不正解
   ↓
回答履歴に保存
   ↓
復習対象になる
   ↓
もう一度挑戦
```

さらに、同じ問題を別のミニゲームで再出題する構想もある。

例：

```text
1回目
Code Target
  ↓ 不正解

復習
Typing Samurai
  ↓ 不正解

再復習
Code Breaker
  ↓ 正解
```

これにより、ミニゲームが単なる装飾ではなく、学習方法の変化として機能する。

# 22. SOLID / KISS / DRY

## SOLID

特にSingle Responsibility Principle（単一責任の原則）を意識する。

例えば、

```text
QuestionService
```

が、

- 問題取得
- スコア計算
- 画面表示
- 復習登録

のすべてを担当するような構造を避ける。

責務を分け、

```text
QuestionService
AnswerService
ScoreService
ReviewService
MiniGameService
```

などに分割する。

## KISS

必要以上に複雑な仕組みを作らない。

## DRY

同じ問題判定・タイマー処理・回答処理などを複数箇所にコピーしない。

を参考にする。

# 29. スコープ管理

今回最も重要なルール：

> **機能を増やすことより、Java Bronze学習システムを最後まで完成させることを優先する。**

優先順位：

```text
① Java学習機能
        ↓
② 問題・回答処理
        ↓
③ DB・履歴・復習
        ↓
④ 4つのミニゲーム
        ↓
⑤ UIの完成度
        ↓
⑥ アニメーション・音
        ↓
⑦ Blender・3D
        ↓
⑧ その他の追加機能
```

Blenderや複雑な演出が原因で本体が未完成になる場合は、追加要素を削る。

# 30. 開発上の基本ルール

### ルール1
まず動くものを作る。

### ルール2
1つの機能を完成させてから次へ進む。

### ルール3
AIが出したコードを理解せずコピーしない。

### ルール4
エラーが出たら原因を理解してから修正する。

### ルール5
同じ処理をコピーして増やさない。

### ルール6
必要以上に機能を増やさない。

### ルール7
既存作品の画面・キャラクター・文章をそのままコピーしない。

# 32. 最終目標

最終的に目指すのは、

**「Javaの問題をゲームっぽく表示するだけのアプリ」ではなく、  
「Javaを学ぶためのWebシステムそのものが、ゲームとして楽しく設計されているアプリ」**

である。

おしゃれなビジュアル、ポップなゲームUI、短いJava問題、キーボード操作、複数ミニゲーム、回答履歴、復習機能を組み合わせる。

そして、見た目だけではなく、

- 分析
- 設計
- 実装

- テスト
- リファクタリング

まで一貫した作品として完成させる。
